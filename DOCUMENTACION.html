1. Objetivo de la Aplicación

El presente proyecto consiste en el desarrollo de una Single Page Application (SPA) altamente responsiva e interactiva, diseñada para la visualización, filtrado y simulación de transacciones comerciales de videojuegos. La plataforma actúa como un agregador de información técnica y de precios en tiempo real, ofreciendo a los entusiastas del sector gaming un panel centralizado inspirado en estándares estéticos y operativos de la industria contemporánea, tales como Steam y Twitch.

El núcleo funcional de la aplicación radica en la convergencia de dos servicios externos líderes: la base de datos de videojuegos de RAWG.io (que aporta carátulas, clasificaciones de edad, metacritic, fechas de lanzamiento y taxonomías de género) y la API de ofertas de CheapShark (que introduce la simulación de precios reales, precios de lista y descuentos porcentuales).

Además de los módulos transaccionales (carrito de compras y catálogo), el sistema está proyectado con estrictas medidas de seguridad a través de un **Escudo Parental (NSFW Shield)** implementado por software para filtrar contenidos adultos inapropiados. Así mismo, la plataforma está provista de mecanismos de tolerancia a fallos mediante estructuras locales de datos en memoria.

2. Tecnologías Utilizadas

El diseño de la arquitectura web se sustenta en componentes modulares modernos con un enfoque de alto rendimiento y bajo acoplamiento:

  • Vue.js 3 (v3.5.32) - Composition API: Utilización exclusiva del paradigma de composición web mediante la directiva <script setup>. Se aprovecha la reactividad de grano fino de Vue 3, reduciendo sustancialmente el coste de renderizado comparado con arquitecturas basadas en Options API.
  • Pinia (v3.0.4):** Almacén oficial de estados centralizados. Su diseño modular y tipado nativo permite orquestar de manera limpia e instantánea los datos del carrito, favoritos, y la sesión del usuario.
  • Vue Router (v5.0.4): Gestor de enrutamiento del lado del cliente. Posibilita la arquitectura SPA mediante la carga diferida (lazy loading) de componentes, transiciones dinámicas entre rutas y el control de historial sin recargas completas del navegador.
  • Vite (v8.0.8): Entorno de construcción (bundler) de nueva generación. Minimiza los tiempos de compilación mediante ESM (ECMAScript Modules) nativos y acelera de forma excepcional la recarga en caliente (HMR) durante la fase de codificación.
  • APIs RESTful Externas: Consumo de servicios en tiempo real de RAWG.io y CheapShark mediante peticiones asíncronas asiladas (Fetch API) con control de CORS.
  • Estilo Puro (CSS3 Vanilla) con Metodología BEM: La maquetación estética se basa en selectores CSS puros organizados bajo la metodología Block, Element, Modifier (BEM). Se eludió conscientemente el uso de frameworks prefabricados (como Tailwind o Bootstrap) para asegurar un control milimétrico sobre el diseño responsivo, las animaciones de transición en los botones y las variables globales de diseño (Custom Properties).
  • Análisis Estático de Calidad (Oxlint & ESLint v10.2.1): Herramientas aplicadas en el flujo de pre-compilación para garantizar la erradicación de variables huérfanas, bucles infinitos u omisión de directivas semánticas de HTML.

4. Decisiones Arquitectónicas Relevantes

Durante el ciclo de desarrollo del sistema, se identificaron desafíos técnicos de alta complejidad relacionados con la resiliencia ante fallos externos y la consistencia en el diseño de interfaces. Para dar respuesta formal a estas exigencias, se implementaron cuatro estrategias arquitectónicas:

4.1. Capa de Servicios con Triple Fallback (Resiliencia de Datos)

Una de las mayores vulnerabilidades en aplicaciones RIA que consumen APIs externas es la dependencia absoluta del servidor de origen. Si la API sufre un corte de servicio o el usuario no configura una credencial de acceso válida, la aplicación colapsa.

Para solventarlo, se implementó un **Patrón de Adaptador con Triple Fallback** en rawgService.js. Si la consulta inicial a RAWG.io falla por red o por ausencia de la API Key, el servicio intercepta el error, degradando progresivamente la llamada en primer lugar hacia la API de CheapShark (que no exige credenciales), mapeando dinámicamente sus campos de ofertas al formato compatible con la interfaz. Si la conexión a internet es completamente nula, el sistema desciende en última instancia a leer la base de datos simulada local mockGames.js. Esto proporciona un sistema robusto con tolerancia a fallos.

4.2. Técnica de Sobremuestreo (Oversampling) en Peticiones

Cuando se efectúan filtros restrictivos del lado del cliente sobre datos ya paginados por el servidor (por ejemplo, omitir juegos que carecen de imágenes de portada o que pertenecen a desarrolladoras sospechosas de spam), surge un problema de diseño: **las páginas de catálogo se vuelven asimétricas**. Un usuario solicita 6 resultados y el navegador muestra 4 en una página y 5 en otra debido al veto de elementos.

La solución implementada consiste en una técnica de **Sobremuestreo (Oversampling)**: en cada consulta al catálogo de RAWG, el servicio asíncrono solicita silenciosamente el triple de registros del tamaño de página real solicitado ($N \times 3$, es decir, 18 registros en lugar de 6). El algoritmo aplica los filtros locales de sanitización de contenido inapropiado y control parental sobre este conjunto expandido de datos. Finalmente, realiza una disección limpia mediante el método .slice(0, 6) para devolver exactamente los 6 juegos óptimos requeridos para llenar de manera exacta la grilla visual de la interfaz.

4.3. Escudo Parental Adaptativo contra Contenido Explícito (NSFW Shield)

Con el fin de asegurar que la aplicación mantenga una orientación apta para todo público (familiar), se desarrolló un algoritmo de inspección y exclusión multi-nivel que veta juegos para adultos sin ocultar juegos de acción comercial masiva clasificados para adolescentes o adultos jóvenes (tales como Call of Duty o GTA V):

  • Exclusión por ESRB: Lectura del slug de clasificación oficial. Si el juego es calificado bajo adults-only, se rechaza de inmediato.
  • Exclusión por Coincidencia Léxica en Título: Se realiza una comprobación de palabras clave (sensible a minúsculas) en la cadena del nombre (e.g. 'hentai', 'porn', 'sex', 'nsfw', 'erotica', 'fap').
  • Exclusión por Tags de Categorías: Inspección recursiva de las palabras clave internas asignadas por RAWG, aplicando exclusión automática si contiene metadatos de naturaleza sexual.

4.4. Retención y Persistencia del Estado en Navegación Bidireccional

Para evitar el comportamiento molesto donde el usuario retrocede desde la ficha técnica de un juego y descubre que se ha reseteado su página de catálogo y término de búsqueda, se diseñó un canal de persistencia que enlaza el store de Pinia directamente con el sessionStorage del navegador.

El store useGamesStore registra los filtros aplicados en el catálogo y la posición numérica exacta de la página en la que se encuentra el usuario. Al retornar desde la vista de detalles, el componente lee esta información persistente en la memoria de sesión, recreando de manera instantánea y asíncrona el catálogo sin necesidad de intervención del usuario.

5. Organización de Componentes, Stores y Composables

La estructura lógica del sistema obedece a un estricto principio de separación de responsabilidades:

5.1. Componentes Visuales (Presentación)

  • `AppNavbar.vue` (Transversal): Administra la cabecera interactiva. Monitorea reactivamente mediante getters de Pinia el conteo del carrito y el número de favoritos. Resuelve dinámicamente el inicio o cierre de sesión del usuario mostrando su avatar personalizado.
  • `GameCard.vue` (Atómico y Reutilizable): Recibe los datos del juego por propiedades (props) y aplica encapsulamiento visual con selectores CSS estructurados bajo BEM. Cuenta con un **Slot Dinámico** en su sección inferior. Esto permite que el catálogo inyecte botones de acción rápida ("Comprar" / "Favorito" con cambio reactivo de corazón rojo), mientras que la vista de favoritos puede inyectar un botón de eliminación especializado con transiciones de color de peligro.

5.2. Gestión de Estado Global (Stores de Pinia)

El almacenamiento global de la SPA se estructura en:

  • `useGamesStore` (Logística de Catálogo y Transacciones): Almacena colecciones reactivas de favoritos y elementos añadidos al carrito (sincronizados síncronamente con localStorage para que persistan al apagar el ordenador del usuario), y almacena el estado de los filtros temporales de búsqueda (sincronizados con sessionStorage).
  • `useAuthStore` (Seguridad y Sesión de Usuario): Simula el control de sesión del usuario, persistiendo en memoria local los datos del cliente logueado (avatar, nombre, saldo) y permitiendo el inicio/cierre dinámico.

5.3. Encapsulación de Lógica de Negocio (Composables)

Se crearon composables reutilizables para desacoplar la vista de la capa lógica de datos:

  • `useFavorites.js`: Centraliza las operaciones dinámicas de alternar favoritos y consultar el listado guardado, exponiendo funciones limpias como toggleFavorite() e isFavorite() a cualquier vista.
  • `useFilters.js`: Vincula en tiempo real los inputs del formulario de filtrado del catálogo (barra de búsqueda, select de géneros y selector de ordenamiento) y propaga automáticamente los cambios al almacén de Pinia mediante observadores reactivos (watch).

6. Instrucciones de Ejecución

Para inicializar el proyecto en entornos locales, es mandatorio contar con **Node.js** instalado. Siga paso a paso las siguientes sentencias en la terminal:

Paso 1: Instalación de Dependencias

npm install

Este comando descargará todos los paquetes necesarios descritos en package.json en la carpeta interna node_modules/.

Paso 2: Asignación de Variable de Entorno de RAWG (Recomendado)

Cree un archivo de nombre .env en el directorio raíz e inyecte la siguiente credencial de demostración para habilitar la consulta directa de videojuegos en el servidor de RAWG: 

VITE_RAWG_API_KEY=58f1ddb99a354758b20f477e5ae05c66

Paso 3: Servidor de Desarrollo con Hot-Reload

npm run dev

Este comando levantará la aplicación sobre el puerto local http://localhost:5173/ de forma instantánea. Cualquier edición de código que realice se reflejará inmediatamente en el navegador.

Paso 4: Auditoría de Calidad y Formato

npm run lint

Ejecuta las herramientas de linter Oxlint y ESLint para auditar el código y corregir de manera automática problemas menores en la sintaxis.

Paso 5: Compilación para Entornos de Producción

npm run build

Genera la compilación de distribución optimizada y purgada de la aplicación en el directorio dist/, lista para ser desplegada en un servidor de producción.
